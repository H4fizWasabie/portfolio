# portfolio

Personal portfolio site for Hafiz Jamali — [portfolio.wasabietech.com](https://portfolio.wasabietech.com).

## Status

This repo currently holds the **deployed static site as a baseline**, committed so the
site has version history and a rollback point. It was previously unversioned: the live
files existed only at `/var/www/portfolio` on the VPS, with no way to revert a change.

A rebuild is planned — Vite + React + TypeScript + Three.js front end, with a small
API backend. See open issues for the design direction.

## Current site (baseline)

Four static pages plus assets, no build step:

| File | Page |
| --- | --- |
| `index.html` | Landing — selected work, working loop, contact |
| `ai-content-lab.html` | Hill's AI Content Lab practice project |
| `ai-lab-prototypes.html` | Prototype index |
| `resume.html` | Resume page (links to `resume/Resume-Hafiz-Jamali.pdf`) |

Design system: Swiss editorial — Helvetica Neue, Swiss Red `#E4002B` accent, hairline
rules, tight display tracking.

### A note on `resume/Resume-Hafiz-Jamali.pdf`

Generated by the `resume-pdf.service` systemd unit on the VPS
(`/home/theoses/.resume-gen/gen.sh`). It is tracked here as part of the deployed
baseline; regenerating it on the VPS does not touch this repo.

## Deploy

**The live site is served from `/var/www/portfolio`, not from this repo.** Caddy
(`/etc/caddy/Caddyfile`, `portfolio.wasabietech.com`) serves it with `file_server`.

There is no automated deploy yet — this repo and the served directory are currently
independent. Anything that ships needs to be copied to `/var/www/portfolio` (or the
Caddy root repointed at a build output). The rebuild should replace this with a real
deploy step.
