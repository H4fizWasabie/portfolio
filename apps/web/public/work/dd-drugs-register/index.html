DD Drugs Register

Production system — A hospital dangerous-drugs register: daily physical vs. system counts per drug, immutable records with audited corrections, and CSV export — the paper register, kept digitally.

The register a ward counts on.Hospital dangerous drugs: physical counts vs. system counts, entries immutable — discrepancies flag themselves, and the ledger reconciles out loud.

Why it exists

A dangerous-drugs register is the book the ward is accountable for. On paper it is a ledger that drifts in silence — a count missed here, a scribbled fix there, and the discrepancy surfaces weeks later in the wrong meeting. This one makes the loop loud: count the bin, compare against the system, flag the ▵, resolve it with an audited correction or leave the flag standing.

Same idea as Procura and PIMS: no subscription, no cloud mascot — a Go binary over SQLite on a hospital server.

What it handles

  • Daily counts — physical vs. system, per drug, per day.
  • Immutable entries — once a count is saved, it is in the book.
  • Audited corrections — mistakes get fixed out loud: a new row pointing at the original, with a reason.
  • Discrepancy flags — ▵ the moment physical and system disagree.
  • CSV export — when the auditor asks for the book, they get a file.

Under the hood

  • Append-only by schema. A unique index allows exactly one original entry per drug per day. There is no edit path — a fix is a correction row referencing the original via corrects_entry_id, carrying a correction_reason. The original stays in the book.
  • Every row has a name. Each entry and each correction records who made it — the counts are attributable to a person, not a session.
  • Go over SQLite, one file. 15.7MB binary, one database file, a backup.sh beside it. Same operating shape as the rest of the fleet.
  • It runs twice on purpose. The ward’s register and an isolated demo (DEMO_MODE=true, its own database and port) so a demonstration can never write in the real ledger.

The honest edges

  • The contents stay private. Drug names, bins and stock levels appear nowhere here — and unlike the rest of this portfolio, the code is not published: the repo is private. The public door is the demo.
  • A register cannot count for you. Skip the daily count and the system knows nothing. The discipline is human; the ledger just makes it impossible to fudge after the fact.
  • Corrections are not erasures. Fixing a mistake leaves the mistake in the book forever, with your name on the fix. That is the feature — and the discomfort.
  • No roadmap claims. Everything above is either in the binary or in the database.
