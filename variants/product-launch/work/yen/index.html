Yen

Carry the assistant into a compact Go runtime.

A Go implementation of the Theoses agent architecture, with conversation continuity and memory across channels.

  • Go
  • Conversation persistence
  • Shared memory

How the agent is organised

Architecture outline; no live agent session shown. This is an authored workflow outline, not an app screenshot.

  1. Enter through a channel
  2. Resolve the canonical conversation
  3. Run the agent and its tools
  4. Persist the conversation and memory

Why it exists

An assistant should retain a conversation’s identity when its owner moves between a terminal, Telegram and a browser.

What I built

I built Yen as a Go agent with a canonical conversation model, shared memory and channel adapters. Its implementation is developed against documented TypeScript behavior rather than treating a similar-looking interface as compatibility.

How it is built

The Go runtime separates channel adapters, conversation identity, model providers, tools and memory. Repository contracts and parity reports record implemented behavior and remaining differences.

What this page does not claim

Yen is a separate Go implementation, not a claim that it has replaced Theoses or achieved complete feature parity. This page shows an architecture outline, not a running agent or an invented chat.
